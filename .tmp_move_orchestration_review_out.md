## 🛑 Verdict : Non, ne déplace **pas** tout. Séparation obligatoire.

Mélanger du code, un sandbox et des scripts Python dans `DOC/` est une **violation structurelle** qui va faire échouer les gates de structure (dont G340, qui analyse très probablement les chemins pour les fichiers applicatifs) et casser les liens relatifs.

---

### 🧱 Pourquoi "Tout déplacer" est une faute (Challenge)

| Risque | Impact |
|---|---|
| **Pollution de la zone doc** | `DOC/` est une zone documentaire versionnée. Des scripts `.py`, des `.ST` et un `_sandbox` n'ont rien à y faire. G340 (ou un gate équivalent) pourrait scanner `DOC/` pour les déclarations/liaisons et y trouver du code non relié → FAIL. |
| **Liens relatifs cassés** | Les 9 Markdown référencent peut-être des fichiers dans `T185_PROPOSAL`. Si on déplace tout sous `DOC/WFLOW/ORCHESTRATION_RAPPORTS`, les chemins deviennent `../../../../../...` ou se cassent. |
| **Cycle de vie mal défini** | `T185_PROPOSAL` est un **artefact de travail** (temporaire). Les 9 rapports sont des **livrables actifs**. Les mettre au même endroit obligera l'utilisateur à archiver le tout ensemble, confondant livrable et brouillon. |
| **Règle ARCHIVES inactive** | Si tu déplaces `T185_PROPOSAL` avec son `_sandbox` dans `DOC/`, tu rends sa consultation confuse et tu ouvres la porte à une migration prématurée vers `ARCHIVES/` (qui est strictement inactif). |

---

### ✅ Recommandation concrète (actions, sans modifier de fichiers)

1. **Créer le répertoire de livrables** :
   → `DOC/WFLOW/ORCHESTRATION_RAPPORTS/` pour **uniquement les 9 Markdown actifs** (rapports/mémos finaux).

2. **Laisser `T185_PROPOSAL` où il est (racine)** ou le déplacer vers un espace de travail dédié (ex. `WORK/ORCHESTRATION_RAPPORTS/T185_PROPOSAL/`) s'il existe un dossier `WORK/` non versionné ou versionné en dev.
   → Ne jamais placer de code exécutable/sandbox dans la zone `DOC/`.

3. **Adapter les liens relatifs dans les 9 Markdown** :
   Si un rapport cite `T185_PROPOSAL/scripts/foo.py`, ne pas le casser. Utiliser le chemin relatif depuis `DOC/WFLOW/ORCHESTRATION_RAPPORTS/` vers la racine du projet :
   ```text
   [Chemin] ../../../ORCHESTRATION_RAPPORTS/T185_PROPOSAL/...
   ```
   Ou intégrer l'extrait de code pertinent directement dans le Markdown si le lien est trop fragile.

4. **Mettre à jour `DOC/README`** :
   Ajouter une entrée dans l'index pour `ORCHESTRATION_RAPPORTS` afin de le rendre "actif" et traçable (évite qu'il devienne une archive morte).

---

### ⚠️ Dernier point (G340)
Je n'ai pas le contenu exact du gate G340, mais s'il scanne `DOC/` pour vérifier que seuls des `.md`/`.adoc` y résident, alors placer des `.py` et `.ST` dedans est un **fail immédiat**. Si tu as la définition exacte de G340, je peux affiner le raisonnement. Mais la règle d'or reste : **Code ≠ Doc**.
