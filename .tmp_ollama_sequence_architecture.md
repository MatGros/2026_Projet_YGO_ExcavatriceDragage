## 1. Standard attendu (synthèse une page)

### Responsabilité et ordre

`PRG_03_Modes_Cycle` est le cerveau Modes/Cycle : il lit les faits qualifiés de
`PRG_02`, les structures IHM et les retours procédés du scan précédent ; il
produit `Auth` et les demandes de cycle, sans écrire de sortie physique
([AF02 §3/§4](../DOC/AF/AF_Partie-02_Architecture_Programme_v3.2.md:218-224),
[fiche PRG03 §1](../DOC/AF/AF_Partie-02_Architecture_Programme/AF_Fiche_PRG_03_Modes_Cycle_v1.0.md:5-17)).
L'ordre est `PRG_02 → PRG_03 → PRG_04 → PRG_05 → PRG_06 → PRG_07` ; un
retard de scan doit être nommé et justifié.

Le POU `PRG_03` reste ST d'orchestration : déclarations d'instances,
constantes et câblage lisible, sans calcul métier ni fusion cachée
(AF02 §2, lignes 193-206). Les machines d'état et calculs résident dans les
FB ; composition plutôt qu'héritage, responsabilité et producteur uniques.

### Interface d'un FB séquenceur / graphe

Le socle applicable est le contrat `standard` dès qu'un FB remonte un défaut ou
pilote une demande d'organe :

- `VAR_INPUT` : `Enable`, `Reset` ; `Reset` est consommé sur front montant.
  Ajouter seulement les entrées métier nécessaires : `Start`/`Abort` si le
  graphe les utilise, faits qualifiés `[HW]`, permissions `[SAFE]` et réglages
  `[CFG]`. `PowerContactorEngaged` est conditionnel et n'est justifié que si le
  FB interlocke réellement l'organe de puissance (AF03 §3, lignes 164-207).
- `VAR_OUTPUT` : `Ready`, `Fault : ST_Fault`. Ajouter `Lifecycle : ST_Lifecycle`
  (`Busy`, `Done`) si le FB porte une machine à états ; pas de doublons plats
  `Error/ErrorId/Busy/Done` en complément (AF03 §3, lignes 164-182).
  Publier l'état typé (`E_*`), l'étape au défaut `<State>AtError` et les
  diagnostics/consignes IHM nécessaires.
- `VAR_IN_OUT` : seulement un bus/DUT réellement partagé et documenté ; le
  propriétaire, l'écrivain unique, lecteurs, unités, polarités, validité,
  invalidité et tests doivent être connus (AF03 §5, lignes 295-310). Les
  internes ne sont jamais exposés.
- Réglages et échanges complexes sont regroupés en DUT. Un DUT privé à un FB
  suit `ST_fb<NomFb>_<Rôle>` (NC-110) ; un bus de domaine public reste `ST_*`.
  Les structures IHM `Cmd/State/Cfg/Bypass` sont la frontière PLC-IHM, jamais
  une permission d'accès aux variables internes.

### Graphe, homing et cycle de vie

- `CASE` sur un enum unique ; états numérotés `X0...Xn`, labels runtime
  `Xn - texte` ; graphe linéaire ou sous-graphes linéaires, transitions explicites.
- Dernière étape normale nommée `Xn_DONE_SYNC`; `ERROR_HOLD` est l'état de
  repli sûr, hors chronologie normale. Capturer `<State>AtError` avant le passage
  en repli (GUIDE_SEQUENCEUR §3-§7, lignes 76-213).
- Porte d'initialisation en tête : `NOT Enable` (et la chaîne de puissance si
  pertinente) neutralise toutes les demandes, revient à la première étape et
  fait `RETURN`. Une perte d'activation ne doit pas reprendre une étape
  intermédiaire (Guide §6, lignes 153-174).
- Le `Reset` acquitte sur front, ne redémarre jamais un mouvement ; cause
  disparue + nouvel ordre explicite sont requis (AF03 §4, lignes 240-270).
- Temporisations de transition nommées (`TON`, commentaire `Xi→Xj`) ; les fronts
  restent locaux si un seul consommateur, centralisés dans `PRG_02_Acquisition`
  s'ils sont partagés (Guide §8-§9, lignes 220-305).
- Le homing doit publier un état fiable, une étape/consigne IHM, des demandes
  d'axes typées et un datum qualifié. La montée couplée est autorisée seulement
  avec les références valides ; la confirmation visuelle de la benne est une
  commande opérateur distincte, non un forçage d'état.

## 2. Écarts constatés — preuves vérifiables

Gravité : C4 = risque de commande/sécurité à bloquer ; C3 = intégrité de
séquence ou diagnostic pouvant conduire à une décision incorrecte ; C2 =
contrat/maintenabilité ; C1 = documentation/style. « À confirmer » est utilisé
quand le code seul ne permet pas de trancher le contrat matériel.

## 3. Points vérifiés conformes (pour éviter les faux écarts)

- Les quatre FB utilisent une machine d'état typée (`E_CycleStep`, `E_DiveSearchState`,
  `E_ExtractionSequenceState`, `E_MachineHomingStep`) et des sorties
  `Fault : ST_Fault`/`Lifecycle : ST_Lifecycle`.
- `FB_DiveSearch` et `FB_ExtractionSequence` exposent un état spécifique au
  défaut (`StepAtFault`) et capturent au site ou via front (`...:179-188` et
  `174-183`) ; il ne faut pas leur attribuer l'absence de ce champ.
- Les fronts locaux `R_TRIG/F_TRIG` existent pour Reset et événements propres au
  FB (`FB_DiveSearch:60-64`, `FB_ExtractionSequence:56-58`,
  `FB_MachineHomingCycle:70-74`). Le défaut identifié porte sur les conditions
  de Reset et les fronts partagés, pas sur leur absence.
- Les sorties de cycle sont des demandes logiques consommées par PRG03/PRG04,
  pas des écritures Q/PDO dans `CODE/G_CYCLE`; l'interdiction de sortie physique
  directe est donc respectée dans ce dossier.

   `STABILIZING`/`ERROR_HOLD` et la documentation. Chaque correction C3/C4 doit
   être suivie d'un test de chronogramme et de G200 sur les producteurs/
   consommateurs concernés.
