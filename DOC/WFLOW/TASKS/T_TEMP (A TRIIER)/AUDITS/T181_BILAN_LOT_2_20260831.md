### T181-07 — FB_SpeedStep MinStepNumber + garde LIMIT ✅ FAIT
**Preuve** (`FB_SpeedStep.st` L15-16, L30-38, L61, L71) :
- `MinStepNumber : INT := 1` (rétro-compatible), `MaxStepNumber : INT := 5` en `VAR_INPUT`.
- Garde DANS l'ordre exigé par l'amendement B : pré-borner le plafond puis le plancher.
  ```
  _MaxStepClamped := LIMIT(1, MaxStepNumber, 5);
  _MinStepClamped := LIMIT(1, MinStepNumber, _MaxStepClamped);   // PLafond gagne : Min ≤ Max
  ...
  StepNumber := LIMIT(_MinStepClamped, SpeedStepReq, _MaxStepClamped);
  ```
- Gate : `SpeedStepReq <= 0 → StepNumber := 0` → **MinStepNumber sans effet si relâche** (TC OK).

**Impact** : FB_Winch appelle `SpeedStep` SANS passer `MinStepNumber` (il reste à défaut 1, neutre).
Le vRAI plancher plongée est injecté PAR FB_Winch (§5) sur `RequestedStep`, puis passé à SpeedStep
via `SpeedStepReq`. Le `MinStepNumber` de ce FB est donc le mécanisme « plancher » structurel prêt,
mais ce n'est pas lui qui porte le plancher plongée — c'est le flux T181-12/13.
