## 2. Ce que j'ai vérifié moi-même à la source

### 2.1 🚨 Le bouton de validation est aussi le bouton homme-mort

`PRG_02_Acquisition.st:609` → `BtnValidation := HwIn.Operator.JoyBtnRaw OR GVL_IHM…Cmd.BtnValidate`

Conséquence : en HX2, machine **à l'arrêt en bas**, l'appui réflexe d'armement produit un front
accepté par les gardes du plan (`WinchesMechanicallyStopped` ✓, manche neutre ✓, capteur libre ✓)
→ **le preset 8,50 m est écrit au point bas**. Référence fausse, machine déclarée référencée.
👉 **Invalidant** : AC2 doit distinguer le bouton IHM du bouton joystick.

### 2.2 🚨 Le cycle ne commande pas le treuil en MAINT_N2

`FB_WinchCmdArbitrationM1.st:56-61` → seul `SEMI_AUTO` consomme `ReqWinch`. En manuel, la
commande réelle vient du joystick / des boutons IHM.
Conséquence : « montée interdite », « dégagement imposé », « palier 1 max » **ne sont pas
exécutables** par le GRAFCET tel que le plan le suppose. La séquence **observe**, elle ne commande pas.
👉 L'interdiction doit passer par les **permis** (safety / arbitrage joystick), pas par `CmdWinch`.

### 2.3 ✅ AC3 est déjà couvert — mon plan v1.0 se trompait

- La DI est passée **directe** à la sécurité (`PRG_04:946-948`, `TRUE` = libre), donc
  `AND NOT TopPositionSensor` (`FB_Safety_Winch.st:376-379`) **arme** la détection **au contact**.
- `CauseMecaDActive` est dans `CausesPowerCutOffActive` (`FB_Safety_Winch.st:523-525`).
→ L'escalade `PowerCutOff` **existe déjà**. Le plan v1.0 affirmait l'inverse (erreur de polarité) : corrigé.

### 2.4 ✅ La fenêtre HX4 n'est pas [8.50..8.80]

Vraies constantes : `CfgStabilizationMinM := 7.50`, `CfgStabilizationMaxM := 9.50`
(`ST_fbMachineHomingCycle_Cfg.st:29-30`). Les commentaires du FB sont faux. Corrigé dans le plan.

### 2.5 ✅ « Écrire 8,50 m » = écrire un offset logiciel

`FB_Encoder_Homing.st:229-231` → `PendingHomingRefRaw := RawPos - TargetPoints` puis
`PresetValue := RawPos` ; la référence retenue est `Calib.HomingRefRaw` (`:265`).
La cote 8,50 m est donc un **offset de calibration**, pas une valeur codeur. À dire tel quel dans le contrat.

### 2.6 ⚠️ Objection dégradée après vérification

« La référence benne partage la cible M2 » : `BucketReferenceRequested` est un **front** de bouton
(`PRG_02:566-568`), pas un état permanent → pas de conflit structurel, mais une **exclusion
mutuelle** à écrire (boutons benne neutralisés pendant le homing).

  *et* datum valide) — fragile sans référence.
