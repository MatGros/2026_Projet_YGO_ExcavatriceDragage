# T164-4 — Diagnostic ST2C / STruCpp (2026-08-27)

## Résultat

`py -3.13 TOOLS/TEST_AUTO_CI/scripts/run_tests.py --fb FB_Encoder` ne lance pas
STruCpp : la conversion ST → IEC échoue avant compilation.

## Cause certaine

`TOOLS/TEST_AUTO_CI/registry.yaml` déclare pour `FB_Encoder` l'ancien nom de
source `ST_FbStatus.st` sous le répertoire commun :

```yaml
- <repertoire commun>/ST_FbStatus.st
```

Ce fichier n'existe pas. Le type réellement consommé par `FB_Encoder`,
`FB_Encoder_Abs` et `FB_Encoder_Homing` est `ST_Status`, défini dans le
fichier actif `ST_Status.st` du même répertoire.

La référence obsolète apparaît aussi dans plusieurs autres entrées du registre :
le défaut est donc transversal d'outillage, pas une régression T164-4B.

## Effet observé

- conversion : `FileNotFoundError` sur l'ancien nom `ST_FbStatus.st` ;
- runner : `KeyError: 'compilation'` secondaire après l'échec de conversion,
  qui masque partiellement le premier diagnostic.

## Correctif requis (hors T164-4B)

1. Corriger les dépendances du registre selon les types réellement déclarés,
   sans remplacement global aveugle ;
2. rendre le runner robuste lorsqu'une conversion échoue (ne pas accéder à une
   temporisation de compilation absente) ;
3. relancer `--fb FB_Encoder`, puis compiler la chaîne T164-4C/4D une fois son
   contrat matériel validé.

## Limite de sécurité

Même une compilation ST2C/StruCpp verte ne prouve pas la sémantique du PDO
EtherCAT de preset. La question matérielle reste tracée dans
`DOC/WFLOW/CONTRACTS/QUESTIONS_T164-4.md`.

### Limite d'harness (documentée)

L'harness STruCpp traite `Calib` (`VAR_IN_OUT`) **par valeur** : les écritures
du FB ne sont pas répercutées dans le `calib` local du test et chaque appel
`fb(Calib := calib)` le réinitialise. Conséquence : les assertions « Reset ne
restaure pas `Calib.HomingRefRaw` » et « la suspicion persiste après Reset »
**ne sont pas testables de façon fiable sur plusieurs scans** dans cet harness.
Le comportement est vérifié **au niveau du code** (`FB_Encoder_Homing.st:275-278`,
reviewer §2) : Reset acquitte le latch, n'écrit ni `Homed` ni `HomingRefRaw`.
Les tests lisent donc les sorties persistantes (`fb.PresetConfirmationFailed`,
`fb.Homed`).
